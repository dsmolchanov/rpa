# Public eval harness assets

Non-sensitive assets only. Sealed materials — holdout tasks, ground-truth
notes for the holdout, external-source snapshots, the quality rubric, and
judge (scorer/verifier) prompts — must NEVER be committed here. They form
the sealed judge package that lives outside every evaluated plugin
installation (`docs/conventions.md` §1; pilot plan, "Atomic seal").

## Eval-runner (pilot plan, prerequisite 5)

- `runner.py` — the harness.
- `mock_sandbox.py` — mock sandbox wrapper proving the harness confines every session (a real deployment registers bwrap/sandbox-exec as `sandbox_cmd`). `run` mode drives one arm on one task in a
  disposable worktree; `score` mode spawns fresh pinned judge sessions.
- `mock_claude.py` — deterministic mock backend with declared accounting
  and selectable failure modes.
- `preflight.py` — the synthetic preflight: proves every capability against
  the mock backend, offline (`python3 runner.py --preflight`).
- `runner-config.example.json` — configuration shape; the filled copy (real
  installation paths + hashes) lives in the private eval workspace.

Capability → proof map (each row is backed by named preflight checks; 151 checks total):

| Capability (plan, prereq 5) | Runner mechanism |
|---|---|
| Installation-hash verification | `hash_tree` (paths + entry types + permission bits + content — an executable-bit flip changes the digest, so mode drift cannot pass verification) + `verify_installation` for **every registered arm** before every run (drift in any arm halts the experiment); the selected arm's verified copy is **mounted into the profile at an arm-neutral path** (`plugins/installation`, neutral profile label) and passed to the backend via the `{installation}` placeholder in `backend_cmd` — command/profile paths never reveal the arm — a command without the placeholder is refused, so no arm can silently run a bare backend |
| Workflow entrypoint invocation | the arm's `entrypoint` (e.g. `/research_codebase`) is prefixed to the extracted task prompt, so the session enters the evaluated workflow rather than answering bare |
| Real Claude stream schema | `parse_transcript` understands both the synthetic mock schema and the real Claude headless stream (`assistant` events with usage/model nested in `message`, `tool_use` content blocks as tool calls, non-null `parent_tool_use_id` = subagent node); **all input-token categories** — fresh, cache creation, cache read — count toward tree-wide cost |
| Per-node model/effort capture | transcript nodes carry `model`; effort must be pinned via the `{effort}` placeholder in `backend_cmd` (a command without it is refused). Nodes reporting effort must match the registered value (`per_node` capture); the real Claude schema exposes no per-node effort, so an all-absent transcript is accepted on the strength of the mandatory pin (`command_pin` capture, recorded per run) — partial reporting is broken capture and invalidates the run. This two-mode policy is registered in the pilot plan (prereq 5); the real-backend preflight must demonstrate the pinned CLI applies the effort flag to the whole session tree |
| One runtime config across arms | `validate_arm_parity` refuses configs whose arms differ in model, effort, or workflow `entrypoint` before any run (a shared non-empty entrypoint is required): installation content is the only permitted arm difference. `validate_arm_topology` additionally requires the registered three-arm topology before EVERY run — direct run mode included — unless the config explicitly declares itself dev (`nonstandard_config: true`) |
| Clean profile | fresh per-run `CLAUDE_CONFIG_DIR` containing only `settings.json` + the mounted installation |
| Filesystem sandbox | production configs must register `sandbox_cmd` — a wrapper (bwrap/sandbox-exec, validated at the real-backend preflight) confining **every evaluated and judge session** to its own workdir + profile (`{workdir}`/`{profile}` expand per session); a clean profile alone is not filesystem isolation — without the sandbox a session could traverse to sealed materials, prior artifacts, or manifests. Dev configs (`nonstandard_config: true`) may omit it; a production `sandbox_cmd` without both `{workdir}` and `{profile}` confinement placeholders is refused (a wrapper that never receives the paths confines nothing) |
| Worktree isolation | disposable detached `git worktree` at the task's pinned `target-sha`, verified clean and matching, removed after the run; destinations are resolved to absolute paths before reaching git, so a relative `--output` cannot split the worktree between two locations. Every session runs in its **own process group** and a timeout kills the whole tree — spawned tool subprocesses cannot outlive the recorded timeout, keep consuming budget, or touch the worktree during cleanup |
| Prompt extraction | only the `## Task prompt` section reaches the session; the marker is required unconditionally — any task without it is refused, never sent whole |
| Config hygiene | `max_infra_retries` is validated as a nonnegative integer (classified infra failure, not an IndexError/ValueError crash); unknown `--arm` values are refused with the configured arm list; every CLI mode — run, schedule, and score — reports expected rejections as structured `infra_failure` JSON, never a traceback (including missing/unreadable/malformed `--config` files, missing/unreadable/non-UTF-8 task files and scoring documents (and every other operator-supplied input — judge prompts, seal manifests, re-fetched drift copies), and structurally invalid configs — the FULL config schema is validated at load — scalar arm fields (installation_dir/sha256/model/effort/entrypoint), every command field (`backend_cmd`, `judge_backend_cmd`, `backend_version_cmd`, `sandbox_cmd`, `drift_fetch_cmd`: non-empty lists of strings), and boolean flags, so a truthy wrong-typed value (`"model": ["opus"]`, numeric `sandbox_cmd`) fails classified at the boundary instead of as a TypeError deep inside a mode, so `{}` never surfaces as a deep KeyError; schedules, run/schedule manifests, scoring batch manifests, judge and run records, seal manifests, and drift reports pass through the same classified JSON-object boundary); `timeout_seconds` must be a positive number (a nonpositive value would count phantom workflow failures without launching the backend); `workflow_abort_exit_codes` must be a typed list of integers (string codes would silently reclassify genuine aborts as infra); every arm must register an explicit `effort` — a missing registration is never normalized to a default; `nonstandard_config` must be an actual boolean (the truthy string "false" would silently select dev mode); manifests and run records are written **atomically** (temp file + fsync + `os.replace`), so a crash mid-write cannot strand a partial JSON that blocks resume |
| Infra vs workflow failure | `InfraFailure` (crash/unparseable/wrong sha) is invalid and **automatically re-executed** (`run_task_with_retries`, bounded by `max_infra_retries`) vs `WorkflowFailure` (timeout/no artifact/registered abort exit → counted, never replaced); `workflow_abort_exit_codes` registers backend exits that mean the workflow itself gave up; a completed run's fresh document must additionally satisfy the research **artifact contract** — `validate_artifact.py` (self-contained: PyYAML when present, a stricter flat-mapping fallback otherwise; real Markdown headings outside full-delimiter-tracked code fences, contract order, non-empty core sections, metadata format checks, run binding — the artifact's git_commit/repository must match the run's pinned target — and the contract basename pattern; raw artifacts are validated STRICTLY: an [anonymized:] marker in a raw document is itself a violation, and the anonymized-copy exemptions exist only behind the explicit --allow-anonymized mode) runs inside the harness and a rejected artifact is a **counted workflow failure** with its defects recorded and the raw copy preserved, never a scoreable replicate; failed-run records preserve tree-wide accounting, including nodes harvested from the partial transcript of a timed-out or aborted session — those partial nodes are validated for model/effort parity first, so runtime drift invalidates the run (infra) instead of counting as a workflow outcome, and a failure whose FAILED SESSION produced no accounting nodes — which can neither be counted (no parity evidence) nor auto-re-executed (timeouts/aborts are never replaced) — **blocks the run outright** (`BlockingInfraFailure`: one attempt, no automatic retry, classified infra with a `blocking` mark) pending operator investigation; nodes from earlier sessions cannot vouch for a continuation that emitted nothing. `timeout_seconds` is a **run-level deadline** shared by the initial session and every continuation — a per-session reset would grant stop-prone arms extra compute |
| Tree-wide accounting | `account()` sums tokens/tool calls per node, main vs subagent subtotals, plus `subagents_spawned` — the max of two independent signals: **distinct child identities** (several messages from one subagent ≠ several subagents) and **Task-launch tool events** (a child that dies before emitting anything still counts as delegation, so the no-subagent policy cannot be dodged). On a normal arm the same gap is a **parity fault**: launch evidence exceeding model-bearing child identities means part of the agent tree ran with no validated model/effort — the run is invalidated (infra), never accepted as completed on main-context evidence alone |
| Schedule-only holdout execution | a production (standard-topology, non-dev) config refuses direct `--arm`/`--task` runs — holdout runs exist only inside the pre-registered schedule, so extra observed runs or undesignated ablation tasks cannot be added; direct runs remain available to dev configs |
| Pre-registered run schedule | `--make-schedule` emits a balanced, seed-recorded randomized interleaving of arm × task × replicate. A standard (holdout) schedule requires the **registered three-arm topology** (arms named `baseline` and `candidate` plus exactly one no-subagent ablation arm — role names are validated, not just counts), **exactly 6 unique holdout tasks covering the six CANONICAL plan archetypes (numbered 1–6, labels validated against registered keywords — free-form labels refused) and all three registered eval repositories (rpa, livekit-voice-agent, neomenu)** — the full coverage matrix, validated from task frontmatter against explicit canonical sets, not cardinality; every holdout task must additionally be **bound to the registered atomic seal** (basename + content digest in the seal manifest, itself verified against `seal_package_sha256`), so arbitrary files with plausible frontmatter can never run as protocol-valid holdout tasks, and **exactly 3 replicates** per cell — anything else requires an explicit nonstandard mark (`--allow-nonstandard`, dev-set tuning only, never holdout — the override itself is retained in the schedule marker, so a standard-shaped dev schedule never masquerades as holdout and reconstructs correctly); replicate counts must be positive integers; a dev-marked config (`nonstandard_config: true`) can never emit a standard schedule, and its mark propagates into schedule + manifest metadata — and the ablation arm must be **explicitly scoped to exactly its two designated tasks** via `schedule_tasks` (two distinct tasks whose `archetype` frontmatter must match the **registered ablation archetypes** — subsystem-explanation and narrow where-is; the scoping key is reserved for the ablation arm — baseline/candidate always run the complete task list). Execution routes **each task to the clone registered for its own `target-repo`** (`--repos NAME=PATH`; task frontmatter may be qualified `owner/repo` or bare — routing, coverage validation, and `--evidence-repos` mapping all share one canonical form, the lowercased final path component, and ambiguous duplicate mapping keys are refused) — the holdout spans several repositories, and one shared checkout can never serve it. `--run-schedule` **reconstructs** the expected schedule from the registered config, the operator-supplied `--tasks` set, and the recorded seed — the file's own arms/tasks/entries are never trusted — executes in recorded order, **persists progress to the manifest after every entry**, and resumes an interrupted schedule at the first unfinished entry, verifying every prior manifest result against its **immutable per-run record** (a fabricated manifest cannot skip backends or feed scoring invented results). Every run writes a **durable in-progress journal before the backend launches** — if the harness dies after a session completes but before the terminal record lands, resume finds the journal and **blocks** (the backend may have executed; an operator must delete the journal to explicitly authorize a re-run) instead of silently adding an observed replicate. The crash window between the atomic run-record write and the manifest update is closed by **orphan adoption**: a uniquely matching unreferenced terminal record (this entry's arm + task) is adopted instead of executed again — the backend already ran, and a second launch would add an unaccounted observed replicate; ambiguous orphans (more than one unattributable terminal record) are refused, and adoption is **bound to the record's own immutable bindings** — every run record stamps the task content digest (which covers the pinned `target-sha`) and the registered runtime-config digest at execution time, so a stale record from an earlier task revision or configuration is never adopted as this schedule's result. The schedule also carries **per-task content digests** (an edited prompt or re-pinned `target-sha` breaks reconstruction and resume, and is refused again at scoring time) plus a **digest of the whole registered runtime configuration** (arm models/efforts/entrypoints/hashes, backend command + version, judge pins, retry/timeout policy); a uniform config change after registration — which arm parity alone cannot see — is refused, and the completion manifest carries a digest of the **entire schedule** (its resume identity), so a resumed run cannot silently mix results from different schedules, task sets, or configurations |
| Ablation no-subagent policy | an arm with `forbid_subagents: true` (the fleet-ablation third arm) fails as a counted workflow failure if its run spawned any subagent, so third-arm differences stay attributable to fleet removal |
| Ritual-stop capture | every pre-artifact response is preserved verbatim in `interventions_log` and mechanically tagged (`question`/`statement`/`empty`), including the **final unanswered stop** of an exhausted run (`answered: false`), so ritual stops stay countable against the zero-ritual-stop pass bar. Counted failures also record their `effort_capture` mode — the audit trail of which effort evidence accepted them |
| Artifact freshness | pre-run snapshot of `thoughts/shared/research/`; only new/modified docs count |
| Anonymization | scored copy gets random run id + masked fingerprint frontmatter — frontmatter is located at the first non-blank line after BOM stripping, never assumed at line 0; score mode enforces blinding at its own boundary — raw `run-*-raw.md` artifacts are refused and fingerprint keys are scanned across the WHOLE document (a BOM or blank line before the opening `---` cannot smuggle researcher/commit/branch identity past the blind judge; overmatching refuses a scorable document, undermatching would unblind the judge) |
| Fresh pinned judge sessions | `--score` = one new session + profile per judge call via `judge_backend_cmd` (must be **mount-free** — an `{installation}` placeholder in the judge command is refused); judge model/effort pinned via `judge_model`/`judge_effort` and validated per node; the judge's **full response text is preserved** as `judge-<scoring_id>-<n>.json`. Judge batches are **atomic and resumable**: progress persists to `scoring-<role>-manifest.json` (state is namespaced by role, so the scorer and verifier passes share one output directory without colliding) **before the first judge launches** — the scoring id survives a crash on the very first document, so a restart resumes under the same id instead of re-judging under a fresh one — and after every judged document, an interrupted batch resumes under the same scoring id at the first unjudged document, a batch with a different identity (seed/manifest/config/role/**ordered** doc list/**drift decisions** — a reordered resume or a corrected drift report is a different batch) is refused, each resumed slot is re-verified against its **atomic judge record** — full-content match plus presentation index and document, so a corrupted or hand-edited batch manifest can never smuggle an invented score past the judge loop (a slot whose judge record is missing is refused, not re-invented), an **orphaned judge record** (written in the crash window before the batch manifest update) is adopted instead of launching a second nondeterministic session, every judge call writes a **pending journal before launching** — a journal without a record on resume blocks the batch (a judge session may have run and lost its outcome; the operator deletes the journal to explicitly authorize a re-judge), while in-process failures retire the journal so clean re-execution stays automatic, and a **completed batch refuses a second pass** — no duplicate nondeterministic scores, no post-hoc batch selection. Documents are presented in a **randomized order derived from the recorded `--scoring-seed`** (reproducible; seed + presentation index recorded per result), and `--evidence-repo`/`--evidence-sha` are accepted only as a pair. Protocol scoring is **bound to the completion manifest** (`--manifest`), which is itself verified against its schedule (digest + one result per entry), against every **immutable per-run record**, and against the schedule **reconstructed from the registered config and the operator-supplied `--tasks` set** — trimming the schedule and manifest together and recomputing digests is refused. The supplied documents must cover every completed scheduled replicate exactly once — subsets, duplicates, or extras are refused — **and each document's contents must match the artifact digest recorded at run time** (an edited or substituted file with the right name is refused). Scoring also re-checks the **runtime-config digest** (judge command/model/effort, backend version, policy fields must equal what the schedule bound) and the **task-file digests** before launching any judge, and routes each document's **task-specific sealed context** (task prompt + ground-truth note, `--task-contexts TASKFILE=CONTEXT`) to its judge via the manifest's run→task mapping — an artifact need not restate its question for the judge to score it against the right ground truth. The seal also records the **role→prompt association** (`judge_prompts`): passing the scorer prompt to a verifier invocation (or vice versa) is refused, and the **task→context association** (`task_contexts` in the seal manifest): a context that is sealed but belongs to a different task is refused, so swapped mappings cannot judge a replicate against another task's ground truth. The judge prompt and every context are **verified against the atomic-seal manifest** (`--seal-manifest`, file → sha256) and read exactly once before any session launches, so an edit after sealing or between judge calls is refused. The seal also registers the **judge session configuration** (`judge_config`: judge command/model/effort) and both `--make-schedule` and score mode validate the runtime config against it — a config changed after sealing but before scheduling cannot slip unregistered judge settings past the digest chain. The seal manifest itself is trusted only through the **`seal_package_sha256` registered in the config** (digest-bound into the schedule before any outcome) — a recomputed seal is refused. External-context tasks (`external-snapshots: true` frontmatter) additionally require **sealed frozen snapshots** (`--task-snapshots TASKFILE=PATH`), seal-verified under **package-relative keys with directory layout preserved** (same-named files in different subdirectories stay distinct), with the **file set enumerated from the seal itself** — a sealed file missing from the supplied copy, or an extra unsealed file, is refused and placed inside the confined verifier workdir, so external claims are checked against the frozen references, never the live web. Scoring such a task runs the **pre-score source-drift gate against the LIVE sources**: the sealed package binds every snapshot to its source URL (`snapshot_sources`), and the harness itself re-fetches each URL through the registered `drift_fetch_cmd` (`{url}`/`{dest}` placeholders; failed fetches are classified infra) and diffs the fetched bytes against the sealed digests — operator-supplied local copies are refused outright (`refetched` paths in the report are rejected: a local path could be the sealed snapshot itself), and the `--drift-report` carries only the explicit per-task entries with materiality adjudications. Drift is computed **once per task** — each sealed source fetched exactly once per invocation — and the verdict applied to **every replicate document** of that task, so a nondeterministic live source cannot split one cell into judged and excluded replicates. A byte change alone is not conclusive: every changed file needs a **recorded materiality adjudication** (verdict + rationale) — material drift makes the task **inconclusive** (recorded, never judged, for scorer and verifier alike), adjudicated-cosmetic drift stays scoreable — and in BOTH outcomes the full adjudication basis (changed keys, verdicts, rationales) is preserved in the result record and hashed into the batch identity, so an excluded task documents its reported basis for exclusion and a corrected material-drift report between interruption and resume is a different batch even when the same task stays inconclusive; ad-hoc scoring requires the explicit `--unscheduled-docs` opt-out |
| Pinned backend version | the exact Claude Code version is registered (`backend_version` + `backend_version_cmd`) and probed before every run and before **every judge session** (per document, recorded in each judge result); version drift between interleaved entries or mid-scoring-batch blocks the run |
| Judge isolation (two roles) | each judge runs rooted **outside the experiment tree**. Blind **scorers** get an empty working directory with filesystem/exec/web tools denied (`JUDGE_SETTINGS`) so they cannot unblind themselves; evidence **verifiers** get a disposable read-only worktree of the frozen evidence with read-only inspection tools allowed (`VERIFIER_SETTINGS`) — and the registered sandbox confines those tools to the evidence worktree, so parent/absolute paths cannot reach manifests or raw artifacts. A judge that times out is an **invalid judge session (infrastructure)**, never a workflow outcome: the batch stays resumable and re-executes only unfinished documents. In manifest-bound batches each document is verified against **its own task's pinned repo@sha** via the `--evidence-repos NAME=PATH` mapping (a single shared checkout is refused); the single `--evidence-repo`+`--evidence-sha` pair serves unscheduled verification only |

CLI:

- run:   `runner.py --config C --arm A --task T.md --repo /path/to/clone`
- score (blind scorer): `runner.py --config C --score --docs D1.md D2.md --judge-prompt J.md --scoring-seed S --manifest runs/schedule-manifest.json` (or `--unscheduled-docs` for ad-hoc/dev scoring)
- score (evidence verifier): with `--manifest`, add `--evidence-repos NAME=PATH ...` (per-task repo@sha); unscheduled: `--evidence-repo /path/to/frozen-clone --evidence-sha <target-sha>`
- schedule: `runner.py --config C --make-schedule --tasks T1.md T2.md --replicates 3 --seed S --schedule-out schedule.json` (non-holdout shapes need `--allow-nonstandard`), then `runner.py --config C --run-schedule schedule.json --repos rpa=/clones/rpa neomenu=/clones/neomenu --tasks T1.md T2.md` (the same registered task set, revalidated; each task routed to its target-repo clone)
- preflight: `runner.py --preflight`

The mock-backed preflight proves the harness mechanics; a **real-backend
preflight** (same throwaway task, `backend_cmd` set to the pinned `claude`
CLI) must pass once before any baseline run — see the pilot plan sequence.
