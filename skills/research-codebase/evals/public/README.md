# Public eval harness assets

Non-sensitive assets only. Sealed materials — holdout tasks, ground-truth
notes for the holdout, external-source snapshots, the quality rubric, and
judge (scorer/verifier) prompts — must NEVER be committed here. They form
the sealed judge package that lives outside every evaluated plugin
installation (`docs/conventions.md` §1; pilot plan, "Atomic seal").

## Eval-runner (pilot plan, prerequisite 5)

- `runner.py` — the harness.
- `build_installs.py` — deterministic builder for the three registered arm
  installations.
- `validate_artifact.py` — the mandatory research-document contract gate.
- `ns_sandbox.py`, `macos_sandbox.py`, and `macos_sandbox_check.py` — the
  production confinement wrappers and operator-host readiness check.
- `step5_operator.py` — fail-closed protocol-v2 operator driver. Its
  conspicuous all-zero sentinel blocks every phase if no clean-sealer digest
  has been registered. Before scheduling, `real-preflight` runs all three
  arms sequentially on the non-holdout rpa@frozen-candidate probe and binds
  the host/config/wrapper/task plus every contiguous run attempt, runtime pin,
  installation hash, accounting record, and minimal-environment policy into
  a receipt; schedule/runs/judging refuse a missing or drifted record set. The
  driver holds one persistent-path advisory lock across every selected phase;
  concurrent operators stop before mutation or backend launch. The default
  phases stop after `runs`; `next` is an explicit judge handoff. That phase
  verifies the immutable completion manifest and the exact global run
  namespace, derives one canonical manifest-order document population
  (passed `-anon` or failed `-diag`, including documents produced by workflow
  failures), and omits only `artifact_gate: not_evaluated` outcomes. It emits
  the scorer command first, then the verifier command that is valid only after
  the complete scorer batch has been structurally revalidated, followed by
  deterministic aggregation.
- `mock_sandbox.py` — mock sandbox wrapper proving the harness confines every session (a real deployment registers bwrap/sandbox-exec as `sandbox_cmd`). `run` mode drives one arm on one task in a
  disposable worktree; `score` mode spawns fresh pinned judge sessions.
- `mock_claude.py` — deterministic mock backend with declared accounting
  and selectable failure modes.
- `judge_contract.py` — the protocol-v2 scorer/verifier response contracts
  and strict, repair-free validators.
- `seal_package.py` — deterministic atomic builder/verifier for a fresh
  protocol-v2 holdout package; its CLI emits only the package digest and task
  basenames.
- `aggregate_results.py` — fail-closed protocol-v2 reconciliation and exact
  median-then-mean aggregation; its output is sanitized for the public
  results record.
- `preflight.py` — the synthetic preflight: proves every capability against
  the mock backend, offline (`python3 runner.py --preflight`).
- `runner-config.example.json` — configuration shape; the filled copy (real
  installation paths + hashes) lives in the private eval workspace.

Capability → proof map (each row is backed by named preflight checks; the
current count is printed by the preflight itself):

| Capability (plan, prereq 5) | Runner mechanism |
|---|---|
| Installation-hash verification | `hash_tree` (paths + entry types + permission bits + content — an executable-bit flip changes the digest, so mode drift cannot pass verification) + `verify_installation` for **every registered arm** before every run (drift in any arm halts the experiment); the selected arm's verified copy is **mounted into the profile at an arm-neutral path** (`plugins/installation`, neutral profile label) and passed to the backend via the `{installation}` placeholder in `backend_cmd` — command/profile paths never reveal the arm — a command without the placeholder is refused, so no arm can silently run a bare backend |
| Workflow entrypoint invocation | the arm's `entrypoint` (e.g. `/research_codebase`) is prefixed to the extracted task prompt, so the session enters the evaluated workflow rather than answering bare |
| Real Claude stream schema | `parse_transcript` understands both the synthetic mock schema and the real Claude headless stream (`assistant` events with usage/model nested in `message`, `tool_use` content blocks as tool calls, non-null `parent_tool_use_id` = subagent node); **all input-token categories** — fresh, cache creation, cache read — count toward tree-wide cost |
| Stream-json CLI compatibility | `with_stream_json_transport` adds the backend-owned `--verbose` flag required by Claude Code 2.1.220 before `apply_sandbox` wraps the command, so a sandbox wrapper's own `--verbose` cannot suppress the backend flag; insertion is idempotent when the registered backend command already carries it. The deterministic mock accepts the real CLI's text default and rejects explicit `stream-json` without `--verbose` while continuing to emit deterministic transcript events for harness tests; named preflight checks cover the wrapper-flag collision, idempotence, and mock argument contract |
| Per-node model/effort capture | transcript nodes carry `model`; effort must be pinned via the `{effort}` placeholder in `backend_cmd` (a command without it is refused). Nodes reporting effort must match the registered value (`per_node` capture); the real Claude schema exposes no per-node effort, so an all-absent transcript is accepted on the strength of the mandatory pin (`command_pin` capture, recorded per run) — partial reporting is broken capture and invalidates the run. This two-mode policy is registered in the pilot plan (prereq 5); the real-backend preflight must demonstrate the pinned CLI applies the effort flag to the whole session tree |
| One runtime config across arms | `validate_arm_parity` refuses configs whose arms differ in model, effort, or workflow `entrypoint` before any run (a shared non-empty entrypoint is required): installation content is the only permitted arm difference. `validate_arm_topology` additionally requires the registered three-arm topology before EVERY run — direct run mode included — unless the config explicitly declares itself dev (`nonstandard_config: true`) |
| Clean profile | fresh per-run `CLAUDE_CONFIG_DIR` containing only `settings.json` + the mounted installation |
| Minimal child environment | protocol v2 constructs every evaluated and judge child environment from the fixed `claude-cli-minimal-env-v1` allowlist (pinned CLI auth, proxy/TLS, locale, HOME/PATH, and sandbox-wrapper inputs). Arbitrary ambient cloud/source-control/developer-tool variables are absent; a secret-canary preflight proves the boundary. Historical v1 reproduction retains its original behavior. |
| Filesystem sandbox | production configs must register `sandbox_cmd` — a wrapper (bwrap/sandbox-exec, validated at the real-backend preflight) confining **every evaluated and judge session** to its own workdir + profile (`{workdir}`/`{profile}` expand per session); a clean profile alone is not filesystem isolation — without the sandbox a session could traverse to sealed materials, prior artifacts, or manifests. Dev configs (`nonstandard_config: true`) may omit it; a production `sandbox_cmd` without both `{workdir}` and `{profile}` confinement placeholders is refused (a wrapper that never receives the paths confines nothing) |
| Worktree isolation | disposable detached `git worktree` at the task's pinned `target-sha`, verified clean and matching, removed after the run; destinations are resolved to absolute paths before reaching git, so a relative `--output` cannot split the worktree between two locations. Every session runs in its **own process group** and a timeout kills the whole tree — spawned tool subprocesses cannot outlive the recorded timeout, keep consuming budget, or touch the worktree during cleanup |
| Prompt extraction | only the `## Task prompt` section reaches the session; the marker is required unconditionally — any task without it is refused, never sent whole |
| Config hygiene | `max_infra_retries` is validated as a nonnegative integer (classified infra failure, not an IndexError/ValueError crash); unknown `--arm` values are refused with the configured arm list; every CLI mode — run, schedule, and score — reports expected rejections as structured `infra_failure` JSON, never a traceback (including missing/unreadable/malformed `--config` files, missing/unreadable/non-UTF-8 task files and scoring documents (and every other operator-supplied input — judge prompts, seal manifests, re-fetched drift copies), and structurally invalid configs — the FULL config schema is validated at load — scalar arm fields (installation_dir/sha256/model/effort/entrypoint), every command field (`backend_cmd`, `judge_backend_cmd`, `backend_version_cmd`, `sandbox_cmd`, `drift_fetch_cmd`: non-empty lists of strings), and boolean flags, so a truthy wrong-typed value (`"model": ["opus"]`, numeric `sandbox_cmd`) fails classified at the boundary instead of as a TypeError deep inside a mode, so `{}` never surfaces as a deep KeyError; schedules, run/schedule manifests, scoring batch manifests, judge and run records, seal manifests, and drift reports pass through the same classified JSON-object boundary); `timeout_seconds` must be a positive number (a nonpositive value would count phantom workflow failures without launching the backend); `workflow_abort_exit_codes` must be a typed list of integers (string codes would silently reclassify genuine aborts as infra); every arm must register an explicit `effort` — a missing registration is never normalized to a default; `nonstandard_config` must be an actual boolean (the truthy string "false" would silently select dev mode). Authenticated byte inputs are consumed from the stable bytes read through a no-follow, single-link descriptor instead of reopening a pathname after validation. Durable state uses fsynced atomic replacement, exclusive creation for claims/initial manifests/handoffs, and fsynced unlink where deletion authorizes progress, so a crash cannot silently authorize a duplicate observation. |
| Infra vs workflow failure | `InfraFailure` (crash/unparseable/wrong sha) is invalid and **automatically re-executed** (`run_task_with_retries`, bounded by `max_infra_retries`) vs `WorkflowFailure` (timeout/no artifact/registered abort exit → counted, never replaced); `workflow_abort_exit_codes` registers backend exits that mean the workflow itself gave up; a completed run's fresh document must additionally satisfy the research **artifact contract** — `validate_artifact.py` (self-contained: PyYAML when present, a stricter flat-mapping fallback otherwise; real Markdown headings outside full-delimiter-tracked code fences, contract order, non-empty core sections, metadata format checks, run binding — the artifact's git_commit/repository must match the run's pinned target — and the contract basename pattern; raw artifacts are validated STRICTLY: an [anonymized:] marker in a raw document is itself a violation, and the anonymized-copy exemptions exist only behind the explicit --allow-anonymized mode) runs inside the harness. A rejected artifact remains a **counted gate/workflow failure** with its defects recorded and raw copy preserved; it never masquerades as gate-passed, while protocol v2 sends its anonymized `-diag` copy to both all-doc judge roles so content quality is measured independently. Failed-run records preserve tree-wide accounting, including nodes harvested from the partial transcript of a timed-out or aborted session — those partial nodes are validated for model/effort parity first, so runtime drift invalidates the run (infra) instead of counting as a workflow outcome, and a failure whose FAILED SESSION produced no accounting nodes — which can neither be counted (no parity evidence) nor auto-re-executed (timeouts/aborts are never replaced) — **blocks the run outright** (`BlockingInfraFailure`: one attempt, no automatic retry, classified infra with a `blocking` mark) pending operator investigation; nodes from earlier sessions cannot vouch for a continuation that emitted nothing. `timeout_seconds` is a **run-level deadline** shared by the initial session and every continuation — a per-session reset would grant stop-prone arms extra compute |
| Tree-wide accounting | `account()` sums tokens/tool calls per node, main vs subagent subtotals, plus `subagents_spawned` — the max of two independent signals: **distinct child identities** (several messages from one subagent ≠ several subagents) and **Task-launch tool events** (a child that dies before emitting anything still counts as delegation, so the no-subagent policy cannot be dodged). On a normal arm the same gap is a **parity fault**: launch evidence exceeding model-bearing child identities means part of the agent tree ran with no validated model/effort — the run is invalidated (infra), never accepted as completed on main-context evidence alone |
| Schedule-only holdout execution | a production (standard-topology, non-dev) config refuses direct `--arm`/`--task` runs — holdout runs exist only inside the pre-registered schedule, so extra observed runs or undesignated ablation tasks cannot be added; direct runs remain available to dev configs |
| Pre-registered run schedule | `--make-schedule` emits a balanced, seed-recorded randomized interleaving of arm × task × replicate. A standard (holdout) schedule requires the **registered three-arm topology** (arms named `baseline` and `candidate` plus exactly one no-subagent ablation arm — role names are validated, not just counts), **exactly 6 unique holdout tasks covering the six CANONICAL plan archetypes (numbered 1–6, labels validated against registered keywords — free-form labels refused) and all three registered eval repositories (rpa, livekit-voice-agent, neomenu)**; protocol-v2 archetype 5 must explicitly declare its external snapshots, so the drift gate cannot be bypassed. Every holdout task is bound to the registered atomic seal, and exactly 3 replicates run per cell; the ablation is scoped to its two registered tasks. Execution routes each task to its named pinned repository. `--run-schedule` reconstructs the schedule from config, tasks, seed, and seal, then persists and re-verifies every result. One nonblocking OS advisory lock covers the complete output state machine (scan → launch → records → manifest); its pathname is intentionally persistent and must not be deleted—kernel release on process death handles recovery without creating a second lock inode. Before judge handoff, the same global audit rejects foreign/superseded run records, orphan artifacts, claims, and terminal-invalid material. Every protocol-v2 run writes a durable schedule-slot-bound journal before backend launch; a surviving post-launch ambiguity terminally invalidates the round, while a safely persisted partial infra sequence continues at its next registered attempt. Retry exhaustion, malformed history, duplicate terminal outcomes (including extras found after a complete manifest), or an ambiguous journal create a persistent terminal-invalid record; deleting one evidence file never authorizes another observation. A unique terminal orphan is adopted without re-execution. Schedule digest/index, task digest, runtime-config/environment policy, and the complete schedule bind every accepted record. |
| Ablation no-subagent policy | an arm with `forbid_subagents: true` (the fleet-ablation third arm) fails as a counted workflow failure if its run spawned any subagent, so third-arm differences stay attributable to fleet removal |
| Ritual-stop capture | every pre-artifact response is preserved verbatim in `interventions_log` and mechanically tagged (`question`/`statement`/`empty`), including a valid partial `result` emitted before timeout/registered abort and the **final unanswered stop** of an exhausted or failed run (`answered: false`), so ritual stops stay countable against the zero-ritual-stop pass bar. Counted failures also record their `effort_capture` mode — the audit trail of which effort evidence accepted them |
| Artifact freshness | pre-run snapshot of `thoughts/shared/research/`; only new/modified docs count. A valid slot has exactly one nonempty document; whitespace-only files are no-document output, while multiple nonempty files preserve byte/digest evidence and terminally invalidate the round instead of selecting one post hoc |
| Anonymization | scored copy gets random run id + masked fingerprint frontmatter — frontmatter is located at the first non-blank line after BOM stripping, never assumed at line 0; score mode enforces blinding at its own boundary — raw `run-*-raw.md` artifacts are refused and fingerprint keys are scanned across the WHOLE document (a BOM or blank line before the opening `---` cannot smuggle researcher/commit/branch identity past the blind judge; overmatching refuses a scorable document, undermatching would unblind the judge) |
| Fresh pinned judge sessions | `--score` = one new session + profile per judge call via the mount-free registered judge command; model/effort are pinned and validated per node, and the full response is preserved. A persistent per-role/axis OS advisory lock covers the complete batch state machine, while exclusive manifest creation elects exactly one scoring id; lock files remain in place and concurrent resumes stop before scanning or launching. Protocol v2 is sequential: the scorer batch must complete first, and the verifier revalidates its full counterpart namespace before its own first backend call. Progress persists after every document; an interrupted batch resumes only unfinished slots, revalidates every atomic record, and adopts a unique valid orphan. A surviving pending journal with no attempt record is ambiguous and terminally invalidates the batch. Schema-invalid responses consume the fixed three-attempt budget, exhaustion is permanent, and a completed batch refuses a second pass. Documents use a seeded randomized order. Scoring is bound to the completion manifest, reconstructed schedule, exact all-document population, artifact digests, runtime/environment policy, sealed role prompt + rubric + schema + task context, judge configuration, snapshots, and live source-drift adjudication. Material drift makes the task inconclusive for both roles and requires a fresh seal; cosmetic drift remains scoreable with its basis bound into batch identity. If no run produced a document, both commands still run with `--docs --manifest ...`: they perform the run/seal/drift audits and create complete zero-result scorer and verifier manifests. Task-level drift receipts are retained even when the external-context task itself has zero produced documents. |
| Protocol-v2 all-document judging | A v2 seal binds the exact scorer and verifier contract documents, quality rubric, role schemas, three-attempt retry policy, and aggregation/telemetry policy. Every judge receives the sealed role prompt + rubric + exact role schema + task context + document in a fixed order; their digests bind the batch and every attempt/result. Every produced document enters both role batches on the single `all-docs` axis, including an artifact-gate rejection; gate status remains an independent mandatory outcome. Each attempt keeps its raw stream, parsed nodes, immutable bindings, and validation defects. Resume recomputes transport, runtime parity, schema, parsed response, accounting, and verifier-derived evidence accuracy; the first valid response binds, while three invalid responses create a terminal exhaustion record that invalidates the round. `aggregate_results.py` reconciles the complete schedule and both judge populations, rejects any foreign batch material, then performs exact rational aggregation without private paths or document prose. Historical protocol-v1 `primary`/`diagnostic` batches remain readable but are never mixed into v2. |
| Pinned backend version | the exact Claude Code version is registered (`backend_version` + `backend_version_cmd`) and probed before every run and before **every judge session** (per document, recorded in each judge result); version drift between interleaved entries or mid-scoring-batch blocks the run |
| Judge isolation (two roles) | each judge runs rooted **outside the experiment tree**. Blind **scorers** get an empty working directory with filesystem/exec/web tools denied (`JUDGE_SETTINGS`) so they cannot unblind themselves; evidence **verifiers** get a disposable read-only worktree of the frozen evidence with read-only inspection tools allowed (`VERIFIER_SETTINGS`) — and the registered sandbox confines those tools to the evidence worktree, so parent/absolute paths cannot reach manifests or raw artifacts. A judge timeout is infrastructure, never a workflow outcome: protocol v2 preserves it as an invalid attempt and proceeds only within the same fixed three-attempt budget; exhaustion is terminal. In manifest-bound batches each document is verified against **its own task's pinned repo@sha** via the `--evidence-repos NAME=PATH` mapping (a single shared checkout is refused); the single `--evidence-repo`+`--evidence-sha` pair serves unscheduled verification only |

CLI:

- run (dev only for protocol v2): `runner.py --config DEV_C --arm A --task T.md --repo /path/to/clone`; a standard v2 config refuses direct runs. The operator's mandatory `real-preflight` is the sole controlled exception: it automatically derives a copy with only `nonstandard_config: true`, runs each arm directly and sequentially in a separate scratch root on the registered non-holdout probe, and never adds those observations to the holdout schedule.
- score (blind scorer, v2): `runner.py --config C --score --docs D1.md ... --judge-prompt SCORER.md --scoring-seed 20260802 --manifest runs/schedule-manifest.json --tasks T1.md T2.md T3.md T4.md T5.md T6.md --task-contexts holdout-v2-1.md=C1.md holdout-v2-2.md=C2.md holdout-v2-3.md=C3.md holdout-v2-4.md=C4.md holdout-v2-5.md=C5.md holdout-v2-6.md=C6.md --seal-manifest sealed/seal-manifest.json --task-snapshots holdout-v2-5.md=sealed/snapshots --drift-report source-drift-v2.json --output judging`. Protocol-v2 scoring is always schedule- and seal-bound; unscheduled mode is historical/dev only.
- score (evidence verifier, v2): only after the scorer command completes, use the same complete argument set and output directory with `--judge-prompt VERIFIER.md`, `--scoring-seed 20260803`, and `--evidence-repos rpa=/clones/rpa livekit-voice-agent=/clones/livekit-voice-agent neomenu=/clones/neomenu`; external-context tasks also require their sealed `--task-snapshots` mapping and one `--drift-report` whose changed-file adjudications contain exactly `observed_sha256` (the live bytes adjudicated), boolean `material`, and a nonblank string `rationale`. The harness requires the observed digest to equal its own live fetch, binding the verdict to those bytes. The operator driver derives `D1.md ...` from the immutable run manifest: gate-passed `-anon.md` and gate-failed `-diag.md`, exactly once each; `not_evaluated` contributes no document.
- protocol-v2 scoring: run the scorer and verifier commands above over the
  same manifest-derived document set; both produce an `all-docs` batch.
  `--diagnostic-axis` is historical protocol-v1 only.
- protocol-v2 operator handoff: schedule seed `20260801`, scorer seed
  `20260802`, and verifier seed `20260803` are prospective constants;
  `step5_operator.py ... --phases next --scorer-seed 20260802 --verifier-seed 20260803 --drift-report source-drift-v2.json`. Existing schedules are reconstructed with the fixed seed before reuse. The pinned judge command is `claude --model claude-opus-5 --effort {effort}`; the emitted commands contain no v1 primary/diagnostic pass.
- schedule: `runner.py --config C --make-schedule --tasks T1.md T2.md T3.md T4.md T5.md T6.md --replicates 3 --seed 20260801 --schedule-out schedule.json` (non-holdout shapes need `--allow-nonstandard`), then `runner.py --config C --run-schedule schedule.json --repos rpa=/clones/rpa livekit-voice-agent=/clones/livekit-voice-agent neomenu=/clones/neomenu --tasks T1.md T2.md T3.md T4.md T5.md T6.md` (the same registered task set, in any order, is canonicalized and revalidated; each task is routed to its target-repo clone)
- seal protocol v2: `seal_package.py --build --package /private/holdout-v2/package --metadata /private/holdout-v2/metadata.json`; later checks use `--verify --package ... --manifest .../seal-manifest.json`. The CLI returns only the manifest SHA-256 and six task basenames.
- aggregate protocol v2: `aggregate_results.py --config C --manifest runs/schedule-manifest.json --scorer-manifest judging/scoring-scorer-all-docs-manifest.json --verifier-manifest judging/scoring-verifier-all-docs-manifest.json --seal-manifest sealed/seal-manifest.json --output results.json`
- preflight: `runner.py --preflight`

The mock-backed preflight proves the harness mechanics; a **real-backend
preflight** (same throwaway task, `backend_cmd` set to the pinned `claude`
CLI) must pass once before any baseline run — see the pilot plan sequence.
