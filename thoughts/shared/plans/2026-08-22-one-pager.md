# One-Pager Digest Implementation Plan

## Overview

Add a **one-pager** capability to the `rpa` plugin: a deterministic, bounded
Markdown (and JSON) digest of "what happened last" in a repository — commits
grouped by pull request, PR/check state, and the state of the repository's
`thoughts/shared/` artifacts (plans and their satisfied/open/not-applicable
criteria and latest enhancement record, test plans, TDD session logs with
achieved phase / cycle state / receipt counts, validation reports, handoffs and
their next steps) — plus a derived **Next** section over *all active*
artifacts and an optional, clearly-marked model-written narrative. The digest
is a *projection* of repository state, so regenerating it is idempotent; it is
refreshed on **events**, never per commit: at the end of rpa sessions (the
`tdd`, `create_handoff`, and `validate_plan` workflows call it), on pushes to
the default branch (a CI job regenerates and publishes it), and on a schedule
for the cross-repository page. Per-repo pages are committed under a new
artifact root `thoughts/shared/one-pagers/`; the cross-repo page is written
outside any repository.

  `plugins/rpa/skills/create-plan/references/artifact-contract.md`),

## Desired End State

1. `python3 <skill-dir>/scripts/onepager.py generate …` exists, is
   stdlib-only, needs only `git` (uses `gh` when present), reads only git,
   `gh`, and contained regular files under `thoughts/shared/`, and emits a
   bounded, deterministic digest: unchanged inputs → byte-identical output,
   including `generated_at` (preserved from the previous digest when the
   canonical facts are identical).
2. `python3 <skill-dir>/scripts/onepager.py validate <file.md|file.json>`
   checks a digest against the contract (structure, bounds, determinism
   markers, Markdown/JSON parity) and exits 0/1/2; `scripts/validate_docs.py`
   binds it to fixtures and discovers committed digests.
3. `/rpa:one-pager` (new skill, user-invocable, Claude + Codex) runs the
   script, optionally appends a ≤ 8-line `## Narrative` labelled as
   model-written, and writes the per-repo page or the cross-repo page.
4. Refresh cadence (event-driven, idempotent): the `tdd`, `create_handoff`,
   and `validate_plan` workflows end by regenerating the per-repo page
   (covering the artifact they just created, even though it is uncommitted); a
   CI job on pushes to the default branch regenerates it and publishes it (job
   summary + artifact + `status/one-pager` branch, with correct permissions,
   concurrency, and a HEAD guard); the cross-repo digest runs on a **local**
   schedule (Claude Desktop scheduled task) — the cloud routine variant is
   documented with its constraints. Nothing regenerates per commit.
5. Plugin version `2.1.0 → 2.2.0`.

Recognizable by: all commands in the **Automated Verification** lists exit 0;
`generate --write` twice on an unchanged repository yields byte-identical
files; a session that only added an uncommitted session log still shows it
under `## Artifacts`; every digest is ≤ 80 physical lines and ≤ 12 KiB with
the newest items and every required heading present; a fabricated, oversized,
or narrative-inventing digest fails `validate` and the docs gate.

### Key Discoveries

- Bounded-projection pattern to mirror for *shape* (per-item cap, counted
  marker, hard cap last): `evidence.py` `build_capsule` / `_bound_capsule` /
  `_item` — but truncation direction must be inverted (drop list **tails** =
  oldest) and structural + narrative capacity reserved before filling lists.
- Gate-binding pattern to mirror: `check_session_log_validator` /
  `check_session_logs` (`scripts/validate_docs.py:676-754`).
- Test style to mirror: `plugins/rpa/hooks/test_run_gate.py`; the TDD tests
  show throwaway git repositories per test; a `gh` PATH shim can return
  canned JSON, malformed JSON, or exit 127.
- Fixed point for `--since last`: when the previous digest's `generated_from`
  equals HEAD, reuse its `window.since`; otherwise advance to its
  `generated_from`. Without this, an unchanged rerun scans `H..H` and empties
  the page.
- Session-end correctness needs the **union** of committed-in-window artifact
  files and dirty/untracked files under `thoughts/shared/` (git status), so the
  artifact that triggered the refresh is listed before it is committed.
- `Next` must scan **all** active artifacts, not only the window, and must
  distinguish satisfied / open / not-applicable criteria.
- Without `gh`, a commit can only be "unattributed", never "direct".
- The "commit on merge to master" variant is blocked by branch protection for
  the Actions token; publishing to a job summary/artifact and an unprotected
  `status/one-pager` branch gives "always current after merge" without a PAT —
  provided the previous page is fetched from that branch for `--since last`,
  the job reads the right workflow run (`ci.yml` at the current SHA), and a
  concurrency group + HEAD guard prevent an older run overwriting a newer
  digest.

## What We're NOT Doing

- No model-generated facts: every number, path, state, and link comes from
  git, gh, or artifact files; the only model-written part is the optional,
  labelled `## Narrative`, which may only restate facts already present.
- No per-commit regeneration, no Claude hook that writes files, no
  auto-commit to a protected default branch, no admin PAT in CI.
- No dev-agent pipeline change here (a one-pager refresh in the dev-agent
  validate stage is a follow-up in `plaintalk-dev-agent`); the publish
  workflow ships in **this** repository only — other repositories adopt it by
  copying `.github/workflows/one-pager.yml` (documented) or via the dev-agent
  bootstrap (follow-up).
- No Slack/Linear posting code; no cloud persistence for the cross-repo page.
- No history/trend store; same-day regeneration overwrites the same file.
- No reading outside git/`gh` and contained regular files under
  `thoughts/shared/` (symlinks, special files, and files > 1 MiB are skipped
  and reported).

## Implementation Approach

One vertical slice owned by a new skill package `plugins/rpa/skills/one-pager/`
(`docs/conventions.md` §1): deterministic operations in `scripts/onepager.py`,
the digest schema/bounds in `references/artifact-contract.md` (single source,
§9), the workflow in `SKILL.md`, the binding in `scripts/validate_docs.py` and
CI (§4), and thin call sites in the three session-ending workflows. Phases are
dependency-ordered: script + contract + tests → validator binding and CI →
skill + workflow call sites + version.

Design decisions fixed by this plan:

- **Paths**: per-repo digest `thoughts/shared/one-pagers/YYYY-MM-DD-<repo>.md`
  (`<repo>` = kebab-cased basename of the repository root; `--json --write`
  also writes `YYYY-MM-DD-<repo>.json` beside it); cross-repo digest
  `$RPA_HOME/one-pagers/YYYY-MM-DD-all.md`, `.json` likewise. Same date →
  overwrite. **`RPA_HOME`** is introduced and owned by the one-pager contract:
  precedence `--out` > `$RPA_HOME` > `~/.rpa`; the directory is created on
  write (mode 0700) and never appears inside any digest's content.
  **Self-reference**: `thoughts/shared/one-pagers/` is *not* an artifact
  source — digests never list themselves or prior digests under `##
  Artifacts` and it has no `## Sources` row. **Paths**: every path emitted in a
  digest is repository-relative (cross-repo pages prefix them with the
  repository's `repo` name); absolute paths never appear.
- **Output-mode matrix** (`generate`): no flag → Markdown to stdout;
  `--json` → canonical JSON to stdout; `--write` → default path(s) for the
  mode (`.md`, plus `.json` when `--json`); `--out <path>` → write to exactly
  that path (Markdown; `.json` companion when `--json`), implies writing;
  `--previous <path>` → use that file as the previous digest for `--since
  last` and `generated_at` preservation (default: the newest file at the
  default path). Per-repo mode: `--out` must resolve inside the repository
  root (realpath, no symlink at target or parent). Cross-repo mode (`--repos`):
  `--out` may be anywhere **outside** every listed repository; `--write` with
  no `--out` goes to `RPA_HOME`; writing into a repository in this mode is
  refused (exit 2).
- **Window and fixed point**: `--since` accepts an ISO date, a git ref, or
  `last` (default). `last`: if a previous digest exists and its
  `generated_from` == HEAD → reuse its `window.since`; else `since` = its
  `generated_from`; no previous digest → 14 days. The digest records only
  `window.since` and `window.head` (= `generated_from`); the previous digest's
  path is **never emitted** (it is machine-specific and would break
  byte-identity) — `window.since`/`window.head` already carry everything the
  fixed point needs.
- **Determinism and `generated_at`**: facts are sorted; the only wall-clock
  value is `generated_at`, and it is **preserved from the previous digest
  when the canonical JSON facts are identical** — so an unchanged rerun is
  byte-identical. `--json` emits the same facts as canonical JSON (`schema:
  1`, `sort_keys`, fixed separators); Markdown is rendered from that JSON and
  the validator checks parity when both files exist.
- **Sources and degradation** (`## Sources` table, one row per source:
  `git`, `gh-prs`, `gh-checks`, `gh-runs`, and one per artifact root
  (`plans`, `tests`, `implementations`, `handoffs`, `research`, `debt`,
  `test-suite` — never `one-pagers`);
  `passed | failed | not_applicable` + reason): `git` required (non-repo →
  `failed`, exit 1); `gh` sources `not_applicable` when `gh` is absent,
  unauthenticated, or there is no GitHub remote, `failed` when `gh` returns
  malformed JSON or a non-zero exit (the digest still renders; exit 0); each
  artifact root `not_applicable` when absent.
- **Read-side containment**: artifact scanning reads only regular files whose
  realpath is inside the repository root and under `thoughts/shared/`; symlinks,
  special files, and files over 1 MiB are skipped and counted in the
  `## Sources` row's reason (`skipped: N symlink/special/oversized`).
- **Facts emitted** (newest-first within each list):
  - `## Window`: `since`, `head`, commit count.
  - `## Landed`: merged PRs in window (`gh pr list --state merged --search
    "merged:>=<since>" --limit 200 --json number,title,mergedAt,author,
    mergeCommit,files`, plus `gh pr view N --json commits` for attribution);
    a commit is attributed to a PR when its sha is the PR's `mergeCommit` or
    in the PR's `commits` list (covers merge, squash, and rebase merges);
    remaining commits are listed as **unattributed** (never "direct"); with
    `gh` absent every commit is unattributed.
  - `## Open`: open PRs (`gh pr list --state open --limit 100 --json
    number,title,isDraft,reviewDecision,headRefName`) with check rollup from
    `gh pr checks N --json name,bucket` → `pass` (all pass/skipping), `fail`
    (any fail), `pending` otherwise.
  - `## Artifacts`: files under each root that are in the **union** of
    committed-in-window changes and dirty/untracked paths (`git status
    --porcelain --untracked-files=all`), each with one status line: plan →
    `satisfied S / open O / not-applicable N` criteria (a criterion line is
    *satisfied* when `- [x]`, *not-applicable* when `- [ ]` and the text
    starts with `Not applicable` / `Not run` / `N/A`, else *open*) and the
    last `### YYYY-MM-DD Enhancement` date; test plan → `[UIE]-\d+` case
    count; session log → `Achieved phase`, `Cycle state`, `receipts:
    <records_through>` (export missing → `receipts: none`); validation report
    → `present` plus the `**Plan**:` target when parseable; handoff → first 3
    bullets found under a bold label or heading matching `Action Items` /
    `Next Steps` (case-insensitive), else `no next-steps section`.
  - `## Health`: default-branch CI rollup from `gh run list --workflow
    ci.yml --branch <default> --limit 1 --json headSha,conclusion,status`
    (the one-pager workflow itself is excluded by naming the workflow), plus
    red checks on open PRs.
  - `## Next` (derived over **all** artifacts, not just the window): plans
    with open criteria (`<open> open in <plan>`), session logs with `Cycle
    state: continuing` or `blocked`, the newest handoff per ticket directory
    with next-step bullets, open PRs whose rollup is `fail`. Not-applicable
    criteria never appear.
  - `## Sources`.
- **Bounds and truncation**: ≤ 80 physical lines, ≤ 12 KiB; bullets ≤ 200
  bytes; capacity is allocated before filling: required headings and fixed
  header lines first, then a **reserve** for the optional narrative (10 lines /
  1 KiB) so appending it can never breach the cap, then lists. Each list is
  truncated at its **tail** (oldest) with a trailing `[+N more]` marker;
  newest items survive. Cross-repo page (`mode: all`): ≤ 160 lines / 24 KiB,
  the same algorithm applied per `## <repo>` section with capacity split
  evenly across repositories.
- **Narrative**: the skill may append `## Narrative` (≤ 8 lines) preceded by
  the marker line `_Model-written summary of the facts above; not a source._`;
  `validate` requires the marker and rejects any **PR reference** (`#N`),
  **repo-relative path** (`thoughts/…`, or any token containing `/` and a file
  extension), **artifact name**, or **count paired with a fact noun** (`N
  PRs|commits|criteria|cases|receipts`) in the narrative that does not occur
  above it; bare digits in prose are not flagged.
- **Validator** (`onepager.py validate <file>`): (a) exact heading sequence
  for the mode (per-repo: the sequence above; cross-repo: `# One-pager (all
  repos)` then one `## <repo>` section per repository, each containing its own
  header block and `### Window/Landed/Open/Next` subsections, then a single
  `## Sources`); (b) header fields — `mode: repo|all` first, then per
  repository `repo`, `generated_from`, `window.since`, `window.head`, and one
  page-level `generated_at`; (c) bounds selected by `mode` (repo: 80 lines /
  12 KiB; all: 160 lines / 24 KiB; bullets ≤ 200 bytes in both); (d) every
  `## Sources` row has a valid outcome; (e) no receipt tokens anywhere (the
  digest cites logs, not receipts); (f) `## Next` bullets are of the allowed
  derived shapes; (g) narrative marker rule; (h) JSON parity when a companion
  `.json` exists (same facts); (i) `.json` input: schema 1, same checks on the
  rendered Markdown; (j) no absolute filesystem paths anywhere. Exit 0
  valid, 1 invalid (`one-pager: <check> — <detail>` per error), 2 usage.
- **Refresh cadence**: (a) session end — `tdd` step 13 (after `export` and
  the session-log validator), `create_handoff` (after writing the handoff),
  `validate_plan` (after writing the report) end with `python3
  <one-pager skill-dir>/scripts/onepager.py generate --write`; failure to
  generate is **reported and non-blocking** for the primary artifact; (b)
  default-branch push — CI job in this repository (below); (c) schedule —
  **local** Claude Desktop scheduled task running `/rpa:one-pager --repos …`
  (documented); the cloud `/schedule` routine variant is documented as
  "selected GitHub repositories, plugin installed in the routine, result
  posted by the routine — no local persistence"; (d) never per commit.
- **CI publish job** (`.github/workflows/one-pager.yml`, this repository):
  `on: push: branches: [master]`; `permissions: contents: write,
  pull-requests: read, checks: read, actions: read`; `concurrency: group:
  one-pager-${{ github.ref }}, cancel-in-progress: false`; steps: checkout
  `fetch-depth: 0`; fetch `status/one-pager` (if it exists) and pass its
  `one-pager.md` as `--previous`; `onepager.py generate --since last --out
  one-pager.md --json`; append to `$GITHUB_STEP_SUMMARY`; upload artifact;
  **HEAD guard** — `git ls-remote origin master` must still equal
  `$GITHUB_SHA`, else skip publishing; push `one-pager.md` + `.json` to
  `status/one-pager` (orphan branch, force). Not a required check.

### 2026-08-22 Implementation note (Phase 1)

Two contract details were corrected while implementing Phase 1; both are
recorded here so the plan and the shipped contract do not disagree.

- **Phase 1 criterion #3 wrote to `/tmp`**, which the round-1 containment rule
  forbids in `mode: repo` (`--out` must resolve inside the repository). The
  criterion now writes inside `thoughts/shared/one-pagers/`. The containment
  rule stands; the criterion was the stale half.
- **The narrative reserve is 13 lines, not 10.** A conforming narrative block
  is a blank line, `## Narrative`, a blank line, the marker, a blank line, and
  up to 8 prose lines. Reserving 10 let a maximal digest reach 83 lines once a
  narrative was appended — exactly the breach round 1 raised. OP-11 now proves
  the corrected reserve holds.

Two decisions the plan left open were fixed in the contract: the digest
filename's date is the **UTC date of the `window.head` commit** (reproducible
from the repository alone, and stable across a session that does not commit),
and a `--out` target is never `realpath`-resolved before the symlink refusal —
resolving first followed the link and let a digest overwrite its target, which
OP-12 now guards.
